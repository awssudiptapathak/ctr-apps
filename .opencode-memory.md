## Project Overview
CTR-CMS = Clubtown Residency Cultural Committee Management System
Mobile-first cultural-event management platform for a residential community.

## Tech Stack (REVISED — plain PostgreSQL, no Supabase)
- **Mobile**: React Native + Expo 53 + TypeScript (apps/mobile)
- **Admin**: Next.js 15.3 + TypeScript (apps/admin) — App Router
- **API/Backend**: Express 4 + `pg` (apps/server) — REST API, port 4200
- **Database**: PostgreSQL 17 (installed standalone at `C:\Program Files\PostgreSQL\17`, Windows service `postgresql-x64-17`, port 5432, db `ctrcms`)
- **Auth**: Custom JWT (`jsonwebtoken`) + bcrypt (`bcryptjs`), passwords hashed & stored in `profiles.password_hash`
- **Shared**: packages/shared (types, constants, validation, utilities, and a fetch-based `api.ts` client)
- **Monorepo**: npm workspaces
- **Tests**: node:test + tsx --test (NOT Jest/Vitest)

## Why not Supabase
Docker cannot start on this machine (hardware/WSL issue — invalid timezone data + Docker daemon fails).
Docker + WSL have been uninstalled. We chose plain PostgreSQL + a custom Express REST API instead.

## API Endpoints (base http://localhost:4200/api)
- `POST /api/auth/register` — {fullName, phone, email, flatNo, password} -> {token, user}
- `POST /api/auth/login` — {phone, password} -> {token, user}
- `GET /api/auth/me` — auth required -> {user}
- `GET /api/auth/profiles` — auth required -> {users}
- `GET /api/events` / `POST` / `GET /:id` / `PUT /:id` / `DELETE /:id` (write = ADMIN)
- `GET /api/programs` / `POST` / `GET /:id` / `PUT /:id` / `DELETE /:id` (write = ADMIN)
- `GET /api/nominations` (own or admin) / `POST` (auth) / `PUT /:id/status` (ADMIN)
- `GET /api/feed` — public events + programs (used by mobile home)
- `GET /api/settings`, `GET /api/health` (checks DB connection)

## Database Schema (17 tables — applied)
profiles, events, programs, program_eligibility, nominations, time_slots,
announcements, campaigns, results, notifications, device_tokens, tickets,
ticket_messages, media_assets, whatsapp_messages, audit_logs, app_settings

**Note**: `profiles` uses `password_hash` + `onboarding_completed` instead of Supabase `auth_user_id`. No `auth.*` schema exists.

## Test-Driven Deployment Convention
- Tests use `node:test` + `tsx --test` (NOT Jest/Vitest). Run a single phase: `npm run test:phaseN`.
- `npm run test:all` runs phases 1-8 (stops on first failure).
- Phase 7 = shared API client unit tests (stubbed fetch). Phase 8 = live API integration tests (require running server, skip if unreachable).
- Before "deploying"/finishing changes: run `npm run typecheck` (all workspaces) + `npm run test:all` + `npm run build --workspace @ctr-cms/admin`.

## Roles
- **USER/Resident**: Browse events, submit nominations, view slots, get notifications, create tickets
- **ADMIN**: Full event/program/nomination/scheduling/announcement management
- **SUPER_ADMIN**: Admin of admins, system settings, role management

## Key Business Rules
- Phone login (this stack: phone + password; OTP flow still mocked on mobile)
- Nominations: OPEN → PENDING → APPROVED/REJECTED/WAITLISTED → SLOT_ALLOCATED → COMPLETED
- Event lifecycle: DRAFT → PUBLISHED → ACTIVE → COMPLETED → ARCHIVED
- Scheduling: manual + automatic with overlap prevention (gist exclusion constraint)
- 10-hour reminder via server-side cron
- WhatsApp: mock in dev, official provider abstraction in production
- Timezone: Asia/Kolkata (store UTC, display IST)
